# Build App Map

An **App Map** shows what ships, on one Claude Design canvas: one board per screen and visually distinct state, recreated from the source at a pinned commit and checked against its snapshots; every navigating control linked, so Play clicks through the app; an Overview page holding the navigation map; a Design kit page showing the design system as it ships (tokens, type, app chrome and components); and a note per row saying where each screen opens from and what is not drawn. Design work never goes on it: each design session keeps its own canvas, registered on the map.

The repo keeps a **mirror** of the canvas, its tools and an `update-app-map` skill, so any later session can bring the map up to date with `main`.

Resolve this skill's installed directory as `<skill-dir>`. `<repo>` is the app repository; `<mirror>` is the App Map folder in it (`ai-docs/designs/app-map/` unless the repo keeps design docs elsewhere); `<root>` is a scratch folder laid out like the mirror: `src/` (the pinned export), `project/` (board files and `canvas.json`, the only files published), `kit/`, `tools/`, `renders/`, plus `inventory.json` and `map.json`. Run every tool from `<repo>` as the working directory.

**Authority.** The Design type's instructions own the file format and call shapes. This skill is the user's request for three things those instructions otherwise rule out: boards generated by a kit script, local render-and-compare checks against the app's snapshots, and publishing in two bulk calls. Check only local files; read back, screenshot or open the live canvas only when the user asks.

## Steps

1. **Scope and pin.** Read the repo's agent instructions. An App Map already exists when `<mirror>/README.md` exists or the Artifact list has "<App> App Map": then use the repo's `update-app-map` skill instead. Otherwise record `main`'s commit and export it: `mkdir -p <root>/src && git -C <repo> archive <commit> | tar -x -C <root>/src`. Read app code only from the export from here on; when `main` moves during the build, finish on the pinned commit (the first drift check afterwards lists what changed). Draw dark copies of the main screens when the app ships a dark appearance with dark snapshots; otherwise light only. Done when the export exists and the commit and appearances are written in `<root>/NOTES.md`.

2. **Inventory every screen and state.** Copy the tools and the kit: `mkdir -p <root>/tools && cp <skill-dir>/scripts/*.py <skill-dir>/templates/config.json <root>/tools/ && cp -R <skill-dir>/templates/kit <root>/kit`, then fill `config.json` for this repo. Follow [references/inventory.md](references/inventory.md) to write `<root>/inventory.json` (schema in `scripts/build_index.py`), Design kit boards included, and `<root>/map.json` (schema in `scripts/gen_map.py`). For a large app, send one surveyor per area ([references/agent-briefs.md](references/agent-briefs.md)) and merge their boards and edges. Check coverage: `python3 <root>/tools/check_drift.py --coverage --repo <repo> --to <commit> --manifest <root>/inventory.json`. Done when coverage reports 0 unclaimed and every board has `sources`, a `presentation`, a `note` and exactly one card in `map.json`.

3. **Create the canvas.** Run the Artifact quickstart with intent `design`, then publish with the returned Design `type_url`, title "<App> App Map" and `auto_open: "after_first_write"`. Read the type instructions it returns and its `artifact-type/reference/format.md` and `diagrams.md`. The app's own code is the look: install a design system only when one belongs to this app. Upload every image a board shows (illustrations, photos, artwork; resize photos to the board's 3x width first) as assets, and record each `/_blob/<id>` with its repo path in `<root>/kit/assets.json`. Done when the canvas `url` is in `inventory.json` and every image has a blob url.

4. **Audit the snapshots and write the kit.** Fill `<root>/kit/chrome.py` with the app's tokens (both appearances when dark copies are drawn), fonts and shared chrome, and write `kit/APPMAP-KIT.md` from its template: tokens, type, geometry measured from the snapshots, components, sample data, and the snapshot traps from the audit in `inventory.md`. Fonts on Google Fonts load through a `css2` link; others are uploaded as font assets. List the local font files in `tools/config.json` so renders match. Done when every colour, size and position a board needs has a source value and each trap is written down.

5. **Calibrate on 5–7 boards.** Pick boards that between them use all the shared chrome: a tab root, a pushed screen, a sheet, an empty or error state, a tall scrolling screen and, when drawn, a dark copy. Draw each in `kit/boards/<area>.py` (delete `example.py`), build (`python3 <root>/kit/build_boards.py --manifest <root>/inventory.json --out <root>/project --only <Names>`), render (`tools/render.py`) and compare with its snapshot (`tools/compare.py`). Fix the kit, not the board, until titles, rows and buttons sit within 2 px. Done when every calibration board matches and its fixes live in `chrome.py` and `APPMAP-KIT.md`.

6. **Build every board.** Draw the rest area by area and build them all into `<root>/project/`. Up to about 60 boards, draw them yourself; above that, give each area to a builder ([references/agent-briefs.md](references/agent-briefs.md)) that owns only its `kit/boards/<area>.py`, while you own `chrome.py` and merge their kit proposals. Done when every screen board builds and `tools/lint.py --pending-ok <root>/project` reports 0 errors.

7. **Draw the Design kit page.** Following the Design kit section of [references/inventory.md](references/inventory.md), draw the Foundations row (tokens, type, app chrome) from the values already in `chrome.py`, then one board per component group with every variant and state the code defines. Where the snapshot suite has kit or component-gallery scenarios, draw each 1:1 from its snapshot. Done when every colour token and type role in the code appears on a kit board, and every shared component has a board showing its variants.

8. **Review against the app.** Render every board and look at one contact sheet per page (`tools/contact_sheet.py`). Compare each board with its snapshot, or with its source when it has none: copy, order, sizes, colours, icons, drawn state and links. For a large map, send one fresh reviewer per area. Fix in the kit or the draw function and rebuild. Done when every board has been compared and its open questions are in its note.

9. **Draw the navigation map.** `python3 <root>/tools/gen_map.py <root>/map.json --out <root>/project/Main.dc.html` prints the map's size; put it in `inventory.json`. Render the map and fix overlapping labels and arrows through `map.json`. Done when the render reads cleanly at full size.

10. **Write the index and check.** `python3 <root>/tools/build_index.py <root>/inventory.json --project <root>/project --manifest <root>/tools/boards.json`, then `python3 <root>/tools/lint.py <root>/project` and `python3 <root>/tools/check_layout.py <root>/project`. Done when both report 0 errors.

11. **Publish in two calls.** First `{url, root: "<root>", file_path: "<root>/project/canvas.json", files: {"project/Main.dc.html": "project/Main.dc.html"}}`, then `{url, root, file_path: "<root>/project/<first board>", files: {…every other board…}}`. Every published path starts with `project/`; split the second call by page when it would pass 16 MB. Done when both publishes are accepted.

12. **Install the mirror and its upkeep.** Copy `project/`, `kit/` and `tools/` (with `config.json` and `boards.json`) into `<mirror>`, and `<root>/map.json` to `<mirror>/tools/map.json`; `inventory.json`, `src/` and `renders/` stay in scratch. Write `<mirror>/README.md` from `templates/README.md` and the repo's `update-app-map` skill from `templates/update-app-map/SKILL.md` into each skill folder the repo keeps (`.claude/skills/`, `.agents/skills/`), filling every `<placeholder>`. Add a line to the repo's skill or rule index that routes screen and design-system changes on `main` to it. Run `python3 <mirror>/tools/check_drift.py`. Done when it lists nothing, or only changes made on `main` after the pinned commit (name them in the report), and no template placeholder is left.

13. **Commit and report.** When committing is authorized, stage only the App Map paths and routing lines (other sessions may have work in the tree) and commit as `docs(designs): add the App Map canvas mirror and its tools`. Report the canvas link (private until the user shares it), pages, screen and kit board counts, appearances drawn, what is not drawn, open questions, and the commit or the uncommitted paths.

## Later changes

The repo's `update-app-map` skill owns every change after the first build: drift, rebuilds, new screens, navigation edits, design canvases and publishing without the Artifact tool. Rebuild `canvas.json` or `Main.dc.html` from scratch only for a full re-layout, after reading the live files and carrying their hand edits over.
